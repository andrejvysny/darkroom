# Native application API

`core-model::catalog` owns the existing camelCase catalog query and read DTOs. `core-library` re-exports their previous paths and retains all SQL, filtering, sorting, paired-image and pagination semantics. `image_by_id` deliberately includes missing records, unlike the present-only library query. The process version and catalog schema are unchanged.

`core-app::ApplicationSession` owns immutable application snapshots and typed commands/completions. It contains no database, filesystem, GUI or GPU dependency. Library, selected-photo/editor identity, active first-slice effects and renderer capability have separate read models. Jobs expose immutable records and admission metrics in the application snapshot. Edit transactions/history, durable writes and preferences remain separate feature services.

Construct a session with injected `Clock`, `EventSink` and renderer-capability ports. `dispatch(Command)` validates enabled state and payload, then returns immutable effects. Execute effects outside the state owner; return each typed `Completion` through `complete`. Never execute an obsolete effect: `is_current` verifies its token and payload. Catalog lifecycle effects must execute in order. Cancellation cannot reverse physical IO. `AsyncCatalogWorkflow` preserves physical lifecycle ordering and final publication fences.

Catalog open/close/reopen/shutdown advance `CatalogEpoch`. Every selection, including the same image and A–B–A, advances editor session and selection generation. Query and metadata requests have independent checked, monotonically increasing IDs. Replaced requests cannot publish old completions; wrong outcome kinds and wrong image IDs are rejected. Accepted query changes clear old rows/count, so failed reads cannot relabel an old result as the new filter. Snapshots remain immutable through shared ownership.

`subscribe` immediately supplies the current snapshot. Each subscription holds one latest `SnapshotUpdate` with a typed notice, revision, timestamp and complete snapshot. Updates coalesce; revision gaps are observable and the snapshot is the recovery source. This is a state-change feed, not a lossless job-terminal event queue. `close` or dropping the subscription tears it down; dead entries are pruned. Event sinks run after subscriber locks are released.

`core-runtime::CatalogAdapter` implements the narrow catalog port with the existing engines. It captures a connection generation, performs SQL with the shared connection lock, releases it, and validates the generation before returning owned values. It owns the `PublicationGate` its hosts mirror under (`core_runtime::sidecar::MirrorService`): every write that changes what a sidecar would contain, or a source identity (edit save, cull, mutation), holds `mutation_guard()` acquired before the catalog mutex and released after the transaction, and every open/close/replacement holds `invalidate_all_guard()` across the slot swap. File open and retired-connection destruction happen outside the slot lock. Replacement/close invalidates in-progress reads and opens. Errors retain actionable categories and original engine error chains. The explicitly named legacy connection bridge is for the Tauri composition root; widget code receives no database or general service locator.

`AsyncCatalogWorkflow` composes paths, clock, event sink, renderer-capability port and effect executor for the native host. The application session stays on the event thread; one catalog effect executes at a time on the supervised executor. At most eight current pending effects are retained, with obsolete queries/selections coalesced. Open/close are durable lifecycle effects and execute in physical order. `pump` never waits for IO; completion wakes the host through a coalesced callback. The host waits for the final close and joins workers before exit. `wait_idle` is the blocking headless adapter. The synchronous `CatalogWorkflow` remains available for compatibility tests.

The five temporary legacy commands `library_query`, `library_count`, `library_folders`, `library_date_tree` and `image_meta` call the same catalog adapter. Startup uses the shared open/error classification and preserves the host's fatal dialog wording. Unmigrated commands share the same connection through the compatibility bridge. Their assigned feature owners remain recorded in `tests/migration/parity`; this does not claim those commands are migrated.

The native host accepts `--catalog PATH` to display real catalog records, select metadata, page, refresh, close and reopen the supplied catalog. `--catalog-probe PATH` exercises open/query/selection/shutdown without a GUI. Neither route discovers a production catalog implicitly. The default no-argument foundation probe and `--gpu-probe` remain available. Catalog open follows existing migrations; qualify using a copy of an existing catalog.

`core-runtime::jobs::Supervisor` owns a fixed worker pool and typed `JobHandle<T>` results. Every job has an ID, catalog/editor owner, class, immutable captured inputs, progress, admission reservation and cancellation state. Ordered lanes serialize per owner and class; latest requests replace pending work and request cancellation of matching running work; deduplication returns the existing job ID. Rejected latest intents also invalidate matching running results, but return explicit backpressure to the caller. Admission never silently drops an accepted durable command. One worker is reserved for foreground commands/viewport work during normal operation; remaining workers choose foreground, visible thumbnails, bulk work, then prefetch.

Count and estimated-byte budgets cover queued, running and retained result payloads until consumption or handle drop. Latest queued replacement reclaims its reservation atomically. Terminal records are bounded; a retained handle can still query its own terminal status after central-history eviction. Progress coalesces independently from the single-consumer terminal result. `CancelRequested` records an intent, not completed cancellation. Running disposable results are discarded at completion; durable successful work reports success even if cancellation was requested after it began. Task/wake panics and worker start/join failures are observable. Task and payload destruction runs outside executor locks.

`ManagedWorkers` owns the small bounded set of long-lived host adapters. Shutdown stops producer admission and the filesystem watcher, sets phase cancellation flags, stops thumbnail/prefetch producers, drains accepted durable executor work, drains sidecar intent, then joins adapters. Phase initialization cannot clear cancellation after shutdown starts. In-flight decode, GPU submission and model training have cooperative boundaries; they are not forcibly interrupted. A shutdown wait is not evidence that unsaved edits became durable; that policy belongs to the persistence service.

The temporary Tauri adapter routes blocking commands through this shared executor. Its default host configuration is three workers, 64 admitted jobs, a 2 GiB estimated reservation budget and 256 central records. Reservations are scheduling estimates, not a hard bound on engine allocations or total process RSS. Per-photo analysis, watcher indexing and feature backfill decode sequentially; numerical engines retain their existing bounded internal parallelism. Infrastructure workers wait for admission outside executor workers, so a full queue cannot deadlock an import waiting to enqueue its follow-up.

Thumbnail/sidecar pending sets are capped at 4096 IDs. Overflow requests a paged catalog rescan rather than losing durable intent; thumbnail pages contain 256 IDs. Prefetch retains at most eight IDs and a five-entry, 384 MiB CPU LRU, rejecting oversized entries. Watcher events occupy one coalesced slot and path traversal streams. Feature backfill retains one coalesced trigger and reads pages of 16 records. Catalog identity/status maps and query result sizes remain proportional to catalog input; reservation metrics do not claim otherwise.

`PublicationGate` fences final sidecar, thumbnail, preview-cache, feature and analysis publication against delete/relink/reset, including replacement that reuses an image ID. Capture source path/hash plus the mutation sequence before unlocked computation; revalidate the token at final publication. Writers acquire the publication gate before the DB mutex. Filesystem operations execute after releasing the DB mutex; source identity mutation waits for final publication. The gate is a short-lived publication barrier, not a document ownership lock. Generic runtime tests use staged files and SQLite rows to exercise paused publication races.

The legacy viewport adapter uses supervisor-assigned host IDs, rather than client counters that restart when a webview reloads. It claims the current image and ticket under the publication barrier before rendering; a delayed older worker cannot replace a newer owner. The React viewport scheduler owns its rAF, pointer/wheel listeners and lifetime generation. Owner replacement/unmount retires pending work, and Stage/Loupe reject late paints. Develop loads selected metadata independently when the Library page has not finished publishing its current rows, so rapid view navigation does not leave rendering permanently gated on missing dimensions.

Suggestion fitting and paged scoring run outside the shared catalog mutex. Candidate model promotion and all computed scores publish in one fenced SQL transaction; interruption before publication preserves the old model/scores. The host rejects scoring beyond one million input rows with an explicit error. Existing synchronous engine wrappers and scoring semantics remain available for compatibility.

The temporary compatibility host still calls legacy culling/deduplication Trash services with a borrowed SQLite connection, including thumbnail garbage collection. Those paths retain the shared catalog mutex across filesystem work. The executor and publication fence do not remove that lock boundary: those services still need a snapshot/work/publish split before the global no-catalog-lock-across-filesystem acceptance criterion can pass. Persistence acknowledgement and durable sidecar outbox policy remain separate from executor shutdown.

The runtime/catalog tests use copied temporary catalogs and deterministic channel-controlled replacement races. Native platform builds still require the codec environment documented in `docs/native-platform-builds.md`. The native host presents the selected photo (SDR) and edits Exposure with undo/redo and durable autosave (below); it does not yet provide other Develop controls, import or export.

## Crate roles in the native host

`crates/ui-egui` owns panels, the Develop panel, stable widget IDs and transient input state (e.g. an active slider gesture); it emits `core_app::workflow::Command`s and never owns authoritative edit state, persistence or retries. It may depend only on `egui`, `core-app` and `core-model`; `cargo xtask layers` rejects runtime, SQL, engine, renderer, wgpu/winit/egui-* and Tauri dependencies (metadata cannot detect direct `std::fs` use; review covers that). `apps/darkroom` owns the winit loop, surface/device/queue, the photo worker and platform services.

## Photo presentation

`apps/darkroom/src/photo_view.rs` reconciles every frame against the snapshot subject (catalog epoch, image, editor session, selection generation) before accepting worker results or building UI: a different subject, a non-renderable document (Loading, Unsupported, Corrupt, Error, missing row, AI-only features) or a closed catalog retires the presented frame immediately. Worker failures are keyed to their own `FrameKey`, shown only while that request is still wanted, and resubmitted only by an explicit Retry. `render_wgpu::Presenter` retires (never drops) replaced leases and rejects every frame while nothing is wanted, so a late result after close cannot present. Retired egui texture registrations and leases are released only after the frame's draw list has been submitted (`after_submit`); later pool reuse is ordered behind it on the same queue. `--photo-probe` reads back the composited egui target and requires a mean absolute difference ≤ 2/255 against the developed frame (measured 0 on the committed CR3).

The photo worker supervises itself: start failure, panic (caught and reported as `WorkerDied`), channel disconnection and join failure are surfaced to the panel instead of an endless spinner. It checks stop/supersession between decode, develop, prepare and render stages and during render-target waits; an in-progress native decode or GPU submission is not interrupted.

## Host scheduling and recovery

Surface acquisition is gated by a retry-not-before instant set by every retry-class surface action; unrelated input/egui redraw requests cannot acquire early (`SurfaceState::schedule`, fake-clock tested). Surface reconfiguration no longer requests a repaint by itself. Occluded/zero-size windows suspend acquisition until visibility or a resize. The host also folds `NativeApplication::next_deadline()` (autosave debounce/backoff, barrier timeout) into its wake schedule.

## Resource bounds

`PreparedImage` allocates its full-resolution mask array, mask scratch and readback buffer lazily (only when masks are enabled, the mask overlay is shown, or a CPU readback is requested); shader behaviour and pixel output are unchanged. `resident_bytes()` and `estimate_prepare_bytes`/`estimate_mask_bytes`/`estimate_readback_bytes` report nominal allocation arithmetic, not measured residency. The photo worker's prepared cache is bounded by a 3 GiB nominal budget (and two entries) and evicts least-recently-used images before an expensive prepare; one image larger than the budget (≈60 MP with masks, large panoramas) opens alone with `over_budget` set. Measured on the 32 MP R7 fixture probe: peak memory footprint 6.15 GB → 5.01 GB; max RSS unchanged at 4.13 GB (CPU decode intermediates dominate and are not yet bounded).

## Legacy host persistence changes (schema 027)

Migration 027 adds `sidecar_outbox.next_attempt_at`. The outbox drains only due intents with keyset paging, so unavailable or failing rows no longer starve healthy ones; failures and missing sources are deferred, never deleted; relink/remount and worker start reset the schedule; a superseding save is due immediately. Sidecars are staged to a unique hidden temp file with no lock held and published by a single identity-checked rename under the publication gate. The updater-restart save barrier no longer occupies the ordered UserCommand lane; acks carry the barrier ID and per-image catalog revisions verified against `edits.revision`, and a timeout never counts as saved. HDR and panorama merges read every source field and capture their publication tokens from one immutable snapshot. Native settings parse the `schema` envelope first, so a newer build's file is left untouched (read-only) instead of being quarantined.

## Native UI shell, Library and Develop

`ui-egui` reproduces the legacy layout: a top bar with Library/Develop/Duplicates modes, search and a catalog menu (gear); Library = catalog/date-folder/file-type nav, virtualized thumbnail grid, info panel (preview, rating/flag/label, histogram, metadata) and a filter/sort/zoom toolbar; Develop = Presets/History rail, stage with zoom/size footer, instrument panel with every global module and a virtualized filmstrip. Colour tokens come from `src/styles.css` (`theme.rs`); icons are painted (`icons.rs`). Sliders take their range/scale from `core_model::controls`; drags are gestures, track clicks/double-click reset/numeric entry/module and top-bar Reset are `EditIntent::Apply`. Culling keys (0–5, P/X/U, 6–9, arrows, G/D) emit `SetCull`/`SelectImage` and are ignored while a text field has focus; a pointer click never gives a slider keyboard focus. Features without a native backend (collections, keywords, people, detected, recent import, AI scan, masks, presets, history, Before/After, WB presets, crop rectangle, denoise, import/export, duplicates, loupe) are shown disabled with "Not in the native app yet" — never with fake data.

The host's `thumbs.rs` serves `ThumbSource`: the UI asks only for cells it lays out; after each frame the pending queue is replaced by the visible misses in visual order. Two workers read the legacy cache tiers (edited → canonical → plain 512 under `<catalog dir>/thumbs`), else generate the plain thumbnail from a source whose BLAKE3 matches the row hash (mismatch = failed, nothing written). Textures live in a 192 MiB byte LRU that never evicts cells requested this frame; an older edit version of the same image stands in while the new one loads. Failures are remembered (≤ 4096) until the catalog epoch changes. After each presented frame the photo worker renders a 256² whole-crop readback for the histogram; it is exposed only for the current subject. On macOS the window uses a transparent full-size titlebar and the SF system fonts when present.

## Known limitations

- The native host drains the sidecar outbox on its own `sidecar-mirror` thread (`core_runtime::sidecar::MirrorService`, fenced by the catalog adapter's `PublicationGate`), but `snapshot.editor.save.mirror` is only read when a save commits: after the drain catches up, the editor keeps showing the save-time `Pending` until the next save reports the new state.
- No grace-discard on native quit: a permanently failing save keeps the app open until the user discards it.
- A crash between staging and publishing a sidecar can leave a hidden `.<name>.<pid>-<n>.tmp` file beside the photo; nothing sweeps them yet.
- Rating/flag/keyword sidecar marks for a temporarily missing source are not re-applied on remount (pre-existing).
- Native display is SDR only; display colour management, HDR output and GPU-device recovery are separate acceptance gates.
- All global Develop sliders are editable natively; drags render at Settled quality (no interactive tier). Border is editable but not previewed. Cull marks are catalog-only (no metadata sidecar).
- An edited image without a cached edited thumbnail shows its unedited thumbnail (legacy fallback); the native host does not render edited thumbnails yet.

## Editing and durable saves

`Command::Edit(EditIntent)` (`BeginGesture`, `UpdateGesture`, `CommitGesture`, `CancelGesture`, `Undo`, `Redo`, `SetExposure`, `Apply`) drives the authoritative editor. The session supplies the live `EditorSession`; a command is refused with a typed `AppError::EditRefused` when there is no Ready document, the stored edit is Unsupported/Corrupt/Error, or the selected image's row (hence its content hash) has not loaded. Nothing is ever defaulted. `ActionId::{Undo, Redo, Edit}` carry enabled conditions from `EnabledContext { editable, can_undo, can_redo }`; `DocumentView` exposes `can_undo`/`can_redo`.

`EditIntent::Apply(Box<DevelopParams>)` is the generic discrete edit: a full-params replacement validated finite and routed exactly like `SetExposure` (one undo step, coalescing, autosave). `Command::SetCull { image, change: CullChange }` (rating 0..=5, `CullFlag`, `Option<ColorLabel>`) issues a durable `Operation::SetCull` on the ordered catalog lane: never coalesced or replaced, refused with `EditRefused("Darkroom is quitting")` once a shutdown barrier is pending, and its `Outcome::CullApplied` patches the matching `library.rows` row and `editor.image` in the snapshot (an old-epoch completion is dropped as stale). Cull marks write the catalog only and queue no `sidecar_outbox` intent, so a rating/flag/label reaches the sidecar with the next edit save; like every other catalog write, the commit holds the adapter's publication fence so the drain cannot publish across it.

Every editor `Changed` event is recorded into `core_app::autosave::Autosave`, keyed by `SaveKey { catalog_epoch, image_id, content_hash }` and ordered by the coordinator's own never-reset `SaveSeq`. Editor revisions restart at 1 in every `EditorSession`, so they only travel as an `EditOrigin` used to decide whether an acknowledgement still concerns the live document: a delayed completion from an earlier session never marks a newer session saved, and at most one save per key is in flight across editor reopen. Reselecting an image whose key still has dirty or in-flight state restores that unsaved state (dirty) instead of the older stored document. Undo history is per session and is not restored; the restored document's single undo step returns to the stored state.

`ApplicationSession::tick(now_ms)` turns due saves into `Operation::SaveEdit { key, seq, params, process_version }` effects and `next_deadline()` reports when to wake. `AsyncCatalogWorkflow::pump` ticks with its `Clock`; hosts schedule a wake from `AsyncCatalogWorkflow::next_deadline()`. `SaveEdit` runs on the ordered catalog lane: one transaction verifies `images.content_hash` equals the key's hash (else `source changed — not saved`) and commits the edit plus the sidecar outbox intent (`save_edit_expecting_source`). The outcome carries the durable `CatalogRevision` and a `MirrorStatus` read in the same call.

`snapshot.editor.save` (`SaveStatus`) reports `dirty`, `saving`, `saved_catalog_revision`, `last_error` and `mirror` separately; a catalog save never implies a mirrored sidecar. The native host runs the drain itself (`core_runtime::sidecar::MirrorService`, started with the application and joined by `pump` once the quit barrier has flushed and the catalog workers are joined — before the workflow closes the catalog), so a queued intent reaches disk without the legacy host. `mirror` is read only inside a save, so it keeps reporting the save-time `Pending { owed_revision }` until the next save, even after the drain has caught up.

`CloseCatalog`, `OpenCatalog` (replacement) and `RequestShutdown` first run a flush barrier: shutdown stops autosave admission, due saves are issued immediately and the operation proceeds only when every captured seq is acknowledged. While a barrier is pending edits and selection are refused. If a save fails the operation is cancelled, admission reopens, `snapshot.error` becomes `AppError::SaveFailed { image, message }` ("Couldn't save your edits to <file>. Darkroom stayed open so nothing is lost.") and the editor stays usable; a second request retries the barrier. There is deliberately no grace-discard in the native host yet. `saved_catalog_revision` is only known after a save in this epoch (it is not read at load). The synchronous `CatalogWorkflow` executes barrier saves inline but has no timer, so it never autosaves on a debounce.

Barrier hardening: `RequestShutdown` is sticky (a pending shutdown refuses `CloseCatalog`/`OpenCatalog` with `EditRefused("Darkroom is quitting")`); autosave admission is derived from barrier kind in one place. A reset (close/replace) is refused with `SaveFailed` while the editor or autosave still holds unsaved work, and `Autosave::retain_epoch` never drops dirty or in-flight entries. A barrier gives up after `BARRIER_TIMEOUT_MS` (30 s, session clock, driven by `tick`) with `SaveFailed`; a timeout never counts as flushed. `AppError::SourceChanged` (the image content hash changed) blocks that autosave entry permanently: it is never retried, a close or quit is cancelled with a `SaveFailed` naming the file, and only `Command::DiscardUnsavedEdits(ImageId)` clears it (refused while that image save is in flight; an open document reloads from the catalog).
