# Model compatibility fixtures

`inputs.json` contains default, process-version 5/6 catalog fixtures, and a full edit covering every serialized field and mask component kind. `legacy.json` was recorded from the frozen pre-extraction `core-pipeline::params` implementation at local baseline `5d75e37cec4cc70a828f2267a6dcfcc4823bedbe`. Original source SHA-256: `params.rs` = `88232a041779501ca512720d9ae139ad1c9e8e482709527bff1f63072e24f117`; `curve.rs` = `69a7596f2498e6f2df6404f827da6141f5efdc99550d6fb5d5ee1815368983a3`. It freezes resolved JSON, every GPU uniform's size/alignment/field offsets, and explicit conversion bytes. `ParamsUniform.exposure` remains at offset 12 inside the `wb_gain` vec3 tail. Shaders and bindings were not changed.

Run `cargo test -p core-pipeline --test model_compatibility` with the normal platform codec environment. The explicit recorder is `cargo run -p core-pipeline --example model_compatibility`; inspect its output before replacing a fixture. Do not refresh fixtures to hide unexplained differences. Numerical pipeline tests additionally cover WB, tone, masks, lens and neutral rendering.

`core-model` contains persistent edit values, typed identity/revision values, and separate CPU UI helpers/control metadata. It has only serde/serde_json dependencies. Import `core_pipeline::GpuParamsExt` or `GpuViewParamsExt` where GPU packing is needed; the trait implementations, GPU ABI structs, and numerical conversion math remain in `core-pipeline`. The legacy `core_pipeline::params::*` type paths still work.

`EditDocument` is a read-only interpretation of a raw edit plus its separately stored process version. Known additive versions 1–6 can expose a typed preview. Unknown fields (including nested fields), unknown enum variants, invalid input, and unsupported versions retain the exact original JSON and expose no preview. No implicit save or destructive merge is provided. Legacy direct serde behavior is unchanged. `validate_finite` rejects non-finite values without clamping finite creative values; callers must use it before serializing edited Rust values, since serde_json otherwise encodes non-finite floats as null. The future application layer must choose explicit reset/migration actions for unsupported documents.

TypeScript geometry fixtures live in `crates/core-model/tests/fixtures/geometry.json`; regenerate explicitly with `node scripts/record-model-geometry.mjs`. The recorder executes production TypeScript functions through esbuild. UI geometry uses f64 inputs where JavaScript rounding and deduplication depend on precision; persisted edit fields remain f32. Conversion from persisted fields is explicit. UI specifications preserve continuous sliders, display precision, value scaling, and the existing bipolar double-click reset behavior (including channel-mixer diagonal reset to zero).

Identity values do not manage application state themselves. The application must advance catalog epochs on reopen/replacement/reset, editor sessions when replaced, and selection generations on every selection, including A–B–A. Device/display/cache/source/edit revisions remain distinct; checked increments refuse wraparound. Application ownership and stale-result publication gates belong to the next migration phases.
